# 资深岗场景与行为

对应简历：10 年经验、求职资深研发、远程协作、从 0 到 1 与接盘存量代码。这一轮常在二面 / 总监面，看判断力和沟通，不看你是否记得某个 API。

## Q1. 用 3 分钟介绍你自己，不要念简历

**怎么答**：见 [专题索引](./2100) 的 60 秒版本，可扩成：

1. 主线：交易资金安全 + 数据平台。
2. 近期：Rust / 桌面 / Agent，证明学习曲线还在。
3. 结果：对账明星项目、多个独立交付。
4. 动机：继续做复杂度高、要稳定上线的系统。

准备 1 分钟和 3 分钟两个版本，面试官说「简单介绍一下」用短的。

## Q2. 你为什么离开 TOP5 交易所数据团队，去做远程 Web3，又去铜锣？

**可能来源**：时间线 2021.09–2023.10 → 2023.12–2025.11 → 2025.12 至今。

**怎么答**：用成长叙事，不贬低前东家：

- 库珀：把对账和数据平台做到可运营，想在链上 / 交易执行侧补完整闭环。
- 远程 Web3：补钱包、多链、自动化执行，锻炼独立交付。
- 铜锣：公司采购交易平台源码，和同事两人搭建上线，把链上经验和存量代码结合，做稳定迭代。

准备好远程怎么协作：需求文档、时区、发布节奏、线上值班。

## Q3. 「10 年全栈」我怎么相信你不是浅尝辄止？

**怎么答**：

给一张深度图，而不是语言列表：

- **深**：Java 微服务、对账、账务一致性、Kafka 消费、MySQL 分片。
- **能独立交付**：Rust 终端 / Agent、Electron 安全模型、Go 策略执行。
- **够用**：Python 采集、Solidity 对接。

然后举一个「我选 Rust 而不是 Java」的具体理由（常驻 Agent、无 GC 抖动、打包成 Windows Service）。选型题比「我都会」更像资深。

## Q4. 给你一个从 0 到 1 的需求，前两周你做什么？

**怎么答**：

1. 写清目标、非目标、成功指标（不要一开始选框架）。
2. 画出数据流和失败路径（钱、权限、审计优先）。
3. 做最窄可用切片：客服就先打通「一个账号发一条翻译消息」；Agent 就先打通「一个工具 + 确认」。
4. 把可观测和发布做成第一批工作，而不是上线后补。

用 ChatCLI 或客服工作台当例子，证明你不是先搭 50 个微服务。

## Q5. 采购的交易平台源码从何下手？

**怎么答**（铜锣：老板买源码，两人搭建）：

- 先跑起来：环境、依赖、配置、中间件，一条充值 / 下单 / 提现的沙盒路径。
- 再画领域图：账户、撮合、钱包边界，分清哪些是源码能力、哪些是你们要改的业务。
- 再动刀：只改要上线的模块，加日志和指标，不重构为快感。
- 风险：不知道的定时任务和历史坑，先列「不可碰清单」；两人分工要能说清谁看撮合/账务、谁看钱包/运维。

## Q6. 跨部门需求冲突时你怎么办？

**怎么答**：用对账或绩效的真实结构：

- 财务要准确，业务要快，研发要可维护。
- 做法：先对齐口径和 SLO，把「准」和「快」拆成不同 SLA（实时看板 vs 日终发放）。
- 你输出：接口契约、指标定义、审批流，减少口口相传。

## Q7. 讲一次你做了但事后证明过度设计的事

**怎么答**：

候选：多链全自建节点、过早上多 Agent、桌面和后端同步做太面。

结构：当时为什么觉得需要 → 成本 / 复杂度 → 如何收缩 → 现在的原则（Adapter 先统一接口，实现按需加链）。

总监面听的是你能砍范围。

---

## Q8. 线上资金类事故，你 30 分钟内怎么组织？

**怎么答**：

1. 止血：停提现 / 停有问题的归集 / 开只读。
2. 定范围：哪些账户、哪些币、哪段时间。
3. 保证据：日志、消息、链上 tx 不覆盖。
4. 对账系统拉差异，而不是先改代码。
5. 通告与双人复核后再恢复。

这题把对账项目的价值说到管理面上。

**怎么答**：

不要虚构下属人数。

## Q10. 反问面试官什么显得你认真？

**怎么答**：准备 3 个和岗位相关的问题，例如：

- 核心链路目前最大的稳定性瓶颈是撮合、账务还是数据？
- 这次招资深，更缺从 0 到 1 还是把存量系统产品化？
- 资金相关变更的发布和回滚流程是怎样的？

避免一上来问加班和薪资（放到 HR 轮）。
