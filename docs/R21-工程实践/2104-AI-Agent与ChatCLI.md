# AI Agent 与 ChatCLI

对应简历：智能体工程化、ChatCLI、Codex / Cursor 使用方式。面试官会区分「会调模型」和「做过 Agent 运行时」。

## Q1. Agent 和 ChatBot 差在哪？你做的是哪一层？

**怎么答**：

- ChatBot：一轮问答，无副作用。
- Agent：模型选择工具 → 执行 → 观察 → 再决策，直到停。
- 你要能画出循环：`用户目标 → 规划 / Function Calling → 工具执行 → 流式事件 → 权限确认 → 写回上下文`。
- 简历中的运行时能力：多 Provider SSE、Tool Use、MCP 子进程、Workspace 沙箱、审计日志。讲项目时点名这些组件，不要只说「接了 GPT」。

---

## Q2. Function Calling 和 MCP 分别解决什么？为什么两个都要？

**怎么答**：

- **Function Calling**：模型输出结构化工具名和参数，应用进程内执行（读文件、bash）。
- **MCP**：工具作为独立进程 / 服务，协议标准化，便于接第三方工具而不把所有实现塞进主程序。
- 一起用：内置高频工具走本地 Function Calling，长尾和外部系统走 MCP。
- 风险：MCP 子进程的权限、超时、stdout 协议破坏、工具描述把上下文撑爆。

---

## Q3. 上下文窗口满了怎么办？

**怎么答**：

- 分层：系统提示（短、稳定） / 工具定义 / 会话摘要 / 最近 N 轮 / 当前任务产物。
- 策略：滑动窗口 + 摘要；工具结果截断；大文件只放路径和片段。
- ChatCLI 场景：终端输出可能极长，Telegram 还要截断和编辑消息，不能把原始 ANSI 全塞回模型。
- 资深点：上下文是产品问题，不是「调大 max_tokens」。

---

## Q4. 多模型 SSE 流式，前端 / Telegram 怎么跟工具调用对齐？

**怎么答**：

- 流里不只有 token，还有结构化事件：`text-delta`、`tool-call`、`tool-result`、`permission-required`、`done`、`error`。
- UI 或 Telegram 按事件状态机渲染，不能假设「一段纯文本」。
- 不同 Provider 的 SSE 字段不同，要有统一内部事件，适配器放边界。
- 失败：半截 tool-call JSON、网络断开、用户取消。要可中止执行并在会话里留下「已取消」。

---

## Q5. 权限确认和 Workspace 沙箱怎么设计才不像摆设？

**怎么答**：

- 工具分级：只读默认放行；写文件 / bash / 外网必须确认或走策略。
- 沙箱：工作目录白名单、禁止任意路径、bash 的 cwd 锁死在 workspace。
- 会话授权：这次允许 ≠ 永久允许；高危命令每次确认。
- 审计：谁在何时批准了哪条命令，事后能翻。这是简历里「安全治理」的落点。

ChatCLI 把 Telegram 当控制面，**默认拒绝未绑定用户**，否则就是远程任意代码执行。

---

## Q6. ChatCLI 为什么用 tmux，而不是直接 pty？

**怎么答**：

- 需求是「离开手机回到电脑，还是同一个 Codex / Cursor 会话」。
- tmux 提供可分离会话：Telegram 只是另一个 client，本机 Terminal 可以 attach。
- 分层：SessionAgent 不管字节流，TerminalManager 管 create / attach / send-keys / capture-pane。
- pty 自己做也能跑，但断线恢复、多窗口、本机接管都要重造。

**追问**：capture-pane 频率、ANSI 清理、Telegram 4096 字限制、消息编辑取代刷屏。这些都是工程细节，能讲就加分。

---

## Q7. 如何防止 Telegram 被盗后打穿开发机？

**怎么答**（必问，主动讲）：

- 控制面身份：只接受白名单 `chat_id`，启动时本机确认配对。
- 命令白名单：不能把任意文本当 shell。
- 敏感操作二次确认（rm、git push、安装依赖）。
- 本机 launchd 服务最小权限，不建议 root。
- 审计日志落本地，异常会话可 `stop`。
- 明确限制：这是个人移动办公工具，不是给不可信网络暴露的生产后门。

不要在面试里演示未授权控制别人的机器。

---

## Q8. 多 Agent 协作怎么避免互相改同一文件？

**怎么答**：

- 子 Agent 任务要有工作区切片（目录 / 文件锁 / 串行队列）。
- 父 Agent 汇总，不让两个子 Agent 同时写一个模块。
- 工具层对同一 path 加租约；冲突时失败并回传观察。
- 这和你简历里「多 Agent 协作与任务编排」对应，没有锁机制就不要把「多 Agent」说得很重。

---

## Q9. 你怎么用 Cursor / Codex 提高交付，而不是变成「AI 写的我不懂」？

**怎么答**：

- 规范沉淀：AGENTS / 规则 / 任务拆分，让模型在仓库约束里改。
- 你负责：任务切分、接口契约、危险变更审查、测试。
- 例子用真实项目：ChatCLI 的分层、客服 DLP 状态机、Agent 的 CI 打包——指出哪段是你定的设计。
- 面试官在听：AI 是杠杆，设计权和事故责任还在你。

---

## Q10. 如果让你在交易系统里嵌一个 Agent，你敢做哪些、不敢做哪些？

**怎么答**：

- 敢：只读研报、解释持仓、生成 SQL 草稿等人审。
- 不敢：直接下单、改风控阈值、提现。必须人在回路。
- 原因：工具一旦有资金副作用，模型和提示注入都是攻击面。
- 这题用来展示你能把 Agent 经验迁到金融场景，而不是只会做玩具。
