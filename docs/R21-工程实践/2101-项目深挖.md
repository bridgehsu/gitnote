# 项目深挖

资深面第一轮几乎都是「挑一个你最熟的项目往下挖」。简历有 10 个核心项目，面试官只会深挖 1～2 个。下面按「你必须先说清楚的边界」来准备。

## 先定三个主项目

不要十个都讲一遍。建议固定三套主叙事，其余当追问备用：

| 优先级 | 项目 | 一句话 | 适合岗位 |
|------|------|------|------|
| 主 1 | 数字资产交易平台 | 撮合 + 账务 + 钱包全链路，最近在做 | 交易 / 资深后端 |
| 主 2 | 多平台企业客服工作台 | 多账号会话 + 翻译 + DLP，可演示 | 全栈 / 桌面 / 跨境 |
| 主 3 | 终端安全监控 Agent | 心跳采集 + 白名单拦截 + 远程清除 | 安全 / 桌面 / Rust |

开场模板：

> 我选数字资产交易平台。这是我最近在做的系统，覆盖现货、合约到钱包充提。我主要在撮合、账务、钱包这条资金链路上做设计和落地，保障生产稳定并持续迭代风控能力。

然后等面试官打断，不要自己把技术栈念完。

## Q1. 这 10 个项目里，哪些是你独立从 0 到 1，哪些是参与？

**可能来源**：简历里「独立研发 / 参与 / 主导」混用。

**怎么答**：

- **独立从 0 到 1**：ChatCLI、终端安全 Agent、自动化执行助手；EVM 资产监测与策略系统的核心模块。
- **主导架构并落地**：对账告警系统；客服工作台的会话 → 翻译 → 发送 → 审计链路。
- **参与核心链路**：数字资产交易平台的撮合 / 账务 / 钱包；绩效系统的工程模块与离线试算；策略交易系统。
- 铜锣科技阶段是**基于既有交易平台源码的二次开发与稳定性**，不要说成自己从零写了整套交易所。

**追问**：如果面试官指着「50+ 微服务」问「你写了几个」，直接说领域和模块，不说虚数。

## Q2. 数字资产交易平台你具体碰了撮合的哪一层？

**可能来源**：「内存撮合、Disruptor、红黑树订单簿」；当前主项目。

**怎么答**：

先画四层，再指自己的落点：

1. 接入：验参、风控、写委托。
2. 撮合：价格优先、时间优先，内存订单簿。
3. 成交回报：账务加减、持仓、强平。
4. 行情：盘口 / 深度 / 成交推送。

简历写的是「参与核心交易与资金链路的设计和落地」。面试里要能讲：

- 为什么用内存撮合而不是每次落库撮合。
- 为什么订单簿用红黑树（按价格有序、撤单 / 吃单要快）。
- Disruptor 用来降低撮合线程和入出队开销，避免普通队列的锁竞争。
- 热数据 Redis、成交异步落 MySQL：崩溃恢复靠什么（快照 + 委托日志 / 消息回放）。

讲不清恢复，就不要把「内存撮合」说成自己的代表作。展开见 [交易撮合与账务](./2102-交易撮合与账务)。

## Q3. 对账告警为什么能评上年度明星项目？你个人贡献怎么切？

**可能来源**：库珀经历里的明星项目。

**怎么答**：

- 业务痛点：资金差异发现晚，财务和运维对账靠人，定位超过 24 小时。
- 你做的事：需求澄清、微服务拆分、Kafka 接入、规则计算、告警与审批流、和数据产品 / 数据服务一起把系统养到可运营。
- 结果口径：日均 5,000+ 资产数据；定位 24h → 1–2h；准确率 99.9%（准备好分母：对平条数 / 应对比条数）。
- 边界：你不是一个人写完所有报表和数仓，强调「从 0 到 1 的系统设计 + 核心模块 + 生产稳定性」。

详细题见 [对账告警与数据平台](./2103-对账告警与数据平台)。

## Q4. 客服工作台为什么选 Electron 而不是 Tauri？自动化助手又为什么选 Tauri？

**可能来源**：简历核心项目 2；两套桌面方案并存。

**怎么答**：

- **客服工作台**：要内嵌 WhatsApp / Telegram Web，依赖 Chromium 生态、WebContentsView、partition 会话隔离，Electron 更合适。
- **自动化执行助手**：核心是调度、代理、CDP、长循环，不需要嵌一整张复杂 Web；Tauri 把逻辑放 Rust 侧，安装包和内存更合适。
- 结论：不是「Tauri 更新所以全换」，而是**嵌浏览器页面 vs 原生能力下沉**两条需求。

## Q5. Windows 终端安全 Agent 的主防线为什么是 NTFS Deny X？

**可能来源**：简历核心项目 3；终端安全项目技术亮点。

**怎么答**：

- 目标：白名单外的程序默认不能执行，而不是事后杀进程。
- Deny 执行权限是文件系统层拦截，比只靠进程名 hook 更靠前。
- 必须承认局限：兼容性差、目录策略要滚动补扫、还要用 WMI / ToolHelp 做进程启动兜底。
- 面试官会问误杀：准备「目录级回退 + 租户白名单 + 远程解除」三件套。

展开见 [桌面端与终端安全](./2105-桌面端与终端安全)。

## Q6. ChatCLI 解决的本质问题是什么？为什么不 SSH？

**可能来源**：近期独立项目，最好演示。

**怎么答**：

- 场景：人不在电脑前，但 Codex / Cursor 还要在**本机真实工作目录**里跑。
- SSH 不够：要的是「已有 GUI / CLI 会话」的续上，而不是再开一个远程 shell；还要和 Telegram 这种移动入口对接。
- 方案：Telegram 收指令 → SessionAgent 理解意图 → TerminalManager 管生命周期 → tmux 保会话 → 本机可 attach 同一窗口。
- 分层原因：会话意图、终端控制和展示（Telegram 消息编辑 / ANSI 清理）必须拆开，否则流式输出和本机接管会互相踩。

安全题是必问，见 [AI Agent 与 ChatCLI](./2104-AI-Agent与ChatCLI)。

## Q7. 绩效系统里「离线指标试算」具体省了什么？

**可能来源**：多点经历、节约 30% 计算成本。

**怎么答**：

- 痛点：方案公式一改就要全量重算，HR 要等到 T+1。
- 试算：用抽样 / 分区 / 已物化的离线指标做公式预演，先验证方案再提交全量作业。
- 结果：少跑无效全量 Spark 作业；绩效从天级到小时级是实时链路 + 工程化调度一起的结果，不要全算在试算头上。

## Q8. ChatCMS、策略交易、EVM 监测这三个项目怎么避免「讲成三个爬虫」？

**可能来源**：采集 / 策略 / 链上项目容易被听成同一类。

**怎么答**，用差异化一句话：

- **ChatCMS**：多源信息 → ES 检索 → 实时推送，偏内容中台。
- **策略交易**：中心化交易所 API 下单与收益统计，偏交易执行。
- **EVM 监测**：社媒信号 + 链上 pending / receipt，偏链上事件驱动执行。

三个都有 Redis，但分别解决去重检索、任务状态、策略状态机，不要用「我用了 Redis」带过。

## Q10. 如果只能讲一个失败项目，你讲哪个？

**可能来源**：资深面必问复盘。

**怎么答**（选一个真实失败，不要编）：

可用框架：

- 目标过度（例如链上自动执行覆盖链太多）。
- 过早优化 / 基础设施成本（多链节点、RPC 费用）。
- 你做了什么止损：收缩范围、抽象 Adapter、用 Redis 去重和状态机把失败可见化。
- 沉淀：多链不要一上来自建全套节点；先做信号准确率和回执跟踪。

简历里 EVM 项目和「风险与基础设施成本评估」很适合当复盘素材，但要说自己的判断，不要甩锅。
